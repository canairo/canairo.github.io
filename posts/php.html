Introductory essay

A quick writeup analysing a fake proof-of-concept for php2shell. php2shell functions as a seriously interesting case study; I think it's the first time people have -- due to their agents -- felt emboldened enough to try making homebrew binary exploitation scripts for a properly challenging attack surface, as opposed to one-liner logic bugs like Log4Shell. The bug underlying php2shell is a significant step up from the old MetaSploit scripts of yore; this is the first time a script kiddie will ever have to account for something like ASLR. Tough stuff! But this is AI as grand democratizer, enabling laypeople to tackle the very frontier of cybersecurity research, a real hearts-and-minds sort of deal. A wonderfully empowering force, to be sure.

I'm kidding. The only laypeople opportunistic and confident enough in their AI systems to try creating an exploit for something like php2shell are -- uniformly -- clueless charlatans. I am not going to make the bold claim that all php2shell scripts published are faulty (that would require a thorough understanding of php2shell as a whole, far deeper than what I have at the moment, in order to verify this sort of thing) but I am making the bold claim that the percentage of slop here is at least 99% of all published exploits. This is what happens when you try to use the robot for a task you don't fully understand: it will cheat, but most importantly it has the integrity to explain to you how it cheated, and if you don't know anything about anything you won't understand that it was cheating in the first place.

A case study: I'd recently written a pwnable for a future CTF competition I'm hosting. ASLR

The one thing the robot always cheats at is ASLR, address space layout randomization. This is a feature of all programs that randomize where critical regions are mapped in memory; at one runtime it might be at point A, at another time it might be at point `A + 0x5ff6050`, or some other random number (like four). Binary exploitation typically involves knowing where the program's structures are in memory; it is no good trying to overwrite important data from within the program if the attacker does not know where it is.

Finding where important structures of the binary are located in memory is colloquially called an ASLR leak; indeed, this is one of the nastiest problems in modern-day binary exploitation. Memory is ephemeral, dreamlike. Not only does it keep moving around on different runs of the binary, the same program at different points in time will invariably have different memory layouts, so on and so forth.

The models are like humans in that they really struggle with this as well. This is because binary exploitation is really two problems: getting your leaks, and then corrupting memory using the information from those leaks.
